# Draft image placement and publication

Follow-up to PR #26: staging upload/preview acceptance passed, but both legacy buttons lost their distinct hero/gallery intent. The private images were not part of the publication operation. This correction completes that transition without making draft objects readable anonymously.

- The administrator uses the existing Hero Carousel and Categorized Gallery controls, with compact production-style private thumbnail cards in those sections; there is no separate Draft images editor. Representatives also have Hero Photos and Gallery Photos groups. Multiple supported files upload sequentially using each returned revision; invalid local files are reported individually and skipped. A server failure stops remaining uploads because its response may be lost after a commit; reload before retrying. Progress and partial completion are visible. Category filters and the sidebar include private images. Private ordering metadata updates do not rehydrate or discard unrelated unsaved editor fields.
- Reordering saves the complete active asset ID order immediately through an authenticated, revision-guarded transaction. Duplicate, omitted, foreign, stale and submitted-state requests are rejected.
- JPG/PNG/PDF uploads store hero/gallery intent and category in server-owned draft asset records. Existing assets default to gallery/exterior and can be reassigned. Assignment, removal and uploads require draft state, current revision and assigned eligible representative or designated administrator authorization. Pending review remains read-only.
- Private images can be selected as hero photos through Pick from Gallery using an asset ID assignment; preview data URLs are not saved as public URLs. Counts include private assignments.
- The authenticated administrator preview fetches private image bytes and uses temporary browser data URLs only in preview state. Those bytes/URLs are never included in Save Draft's public media configuration. Hero and gallery actions retain their original intent; categorized uploads retain the selected category.
- A verified administrator publication request preflights current dealer eligibility, captures listing/media/asset revisions, creates separate public copies with validated MIME types and matching extensions, then atomically commits the status transition, media placement and copy registrations. It rechecks eligibility and captured revisions before the commit. The original private objects remain private and retained.
- Subsequent administrator media saves merge registered publication copies, preventing a stale editor from discarding freshly promoted images. Republishing replaces prior registered placements rather than duplicating them.
- Storage and Firestore cannot commit atomically. A failed publication reconciles committed asset registrations before cleanup, and removes only attempt-owned copies with generation guards. A process termination or unavailable cleanup backend can leave unreferenced public copies requiring reconciliation; there is no claim of atomic cross-service rollback. A publication request authorizes those public copies; they may exist before the status transaction commits. No live publication or cleanup is performed while developing this correction.
- Copy concurrency is bounded to four images, with at most 100 images per request. Large multi-listing publications must be done individually. All files are limited to 2 MiB each. Hero accepts JPG/JPEG and PNG; Gallery also accepts PDF. PDFs are forced into Docs & Records and cannot be hero or chapter photos. Both private previews and public PDF copies use attachment disposition; the editor offers a document download rather than embedding active PDF content. Validation checks format boundaries and MIME/byte agreement, not malware scanning or full document sanitisation.

Validation covers hero/gallery/category preservation, authenticated preview, private denial before publication, public copies after explicit administrator publication, retained private sources, stale media saves, republish deduplication, unauthorized assignment/publication, stale revisions and concurrent image-change cleanup. Owner visual review, staging merge and production promotion remain separately pending.

Owner-requested card refinement: the upload button determines Hero/Gallery placement; there is no per-card placement dropdown. Hero cards retain lead/position badges and drag/arrow ordering. Gallery cards retain compact category and trash overlays, replace photo filename strips with Left/Right ordering, and retain document titles. Clicking photos opens a larger preview. When a category filter is active, arrow ordering swaps adjacent visible items while keeping filtered-out slots unchanged. Existing stored titles/captions are preserved. Private PDF uploads are supported only as gallery documents.
