# Public polling read budget

November 15, 2026: owner screenshots show substantial Firestore reads overnight while the AI-shared-quota database returned RESOURCE_EXHAUSTED. The graph does not attribute requests to callers. Vercel Hobby runtime-log retention did not cover the overnight window; the available last-30-minute grouped runtime log query returned no records, not proof of zero requests.

Confirmed source behavior: public lot detail requests previously repeated every five seconds for every public status, rereading the auction, media, all matching bids/comments and applicable dealer profile. Catalog requests run every 30 seconds, including while a detail page is open. Each HTTP request can bill multiple document reads; HTTP request count is not a document-read count. Hidden-tab polling is already paused. Direct Firebase listeners/other callers are separate and not attributed by this analysis.

The focused correction retains five-second updates for active/live/ending_soon lots and upcoming lots within one minute of their scheduled start. Other detail states refresh every 60 seconds. Catalog retains its 30-second cadence. Failed public requests back off at 30, 60, 120, 240 and at most 300 seconds; a successful response resets cadence. Missing public lots refresh at the slower interval. No overlapping requests, abort-on-hide and refresh-on-return remain in place.

For one continuously visible non-live detail tab this changes the nominal ceiling from 720 to 60 requests/hour (about 92% fewer), before request duration. It does not change the records each successful request reads, eliminate catalog traffic, establish the overnight cause or guarantee that the free daily quota is sufficient. Live bidding freshness is deliberately preserved. No billing upgrade, database mutation or scheduler activation is part of this fix.

Verification uses fake timers and local synthetic tests, not the exhausted production database. Required post-deployment observation: close old app tabs, open a fresh page to load the changed client, confirm non-live/live/near-start cadence and hidden-tab pause in browser Network tools, then compare request/read metrics over a bounded period. Old loaded clients continue their old polling behavior until refreshed/closed. Do not resume quota-blocked public service or rerun completed Storage migration/token phases to test this change.
